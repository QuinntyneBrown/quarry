# Separate database access

Runtime connections now resolve independently: `ConnectionStrings:QuarryRead` for public catalog/search/health reads, `QuarryMaintenance` for authenticated metadata operations and rebuild, and `QuarryWorker` for the indexing host. EF tooling uses `QuarryMigrations`. Existing local/test setups can still fall back to `Quarry`; that legacy shared connection is not a claim of restricted database identity. Configure distinct principals to enforce the boundaries in a running installation.

The migration creates three database roles. `QuarryRead` can read catalog, vectors, index work, catalog revision, and publication timestamps; it cannot read drafts or snapshot metadata and has no mutation grants. `QuarryMaintenance` can maintain current metadata, append snapshots/audit, schedule jobs, and invalidate vectors, but cannot change prior audit/snapshots or schema. `QuarryWorker` can read published metadata, manage index jobs, and replace vectors; it cannot edit metadata, drafts, history, or audit. Migration privileges are never granted to a runtime role.

ATDD on 2026-09-10: the initial tests failed because role-specific connections were ignored and roles did not exist. Four SQL-backed tests now verify independent read/maintenance outages; real permission denial for public writes/private reads; restricted-worker scheduling and completion; and maintenance creation/publication/rebuild with forbidden history/schema mutations. The read role also successfully performs health queries. Tests use isolated SQL users without logins and `EXECUTE AS USER` to exercise database grants rather than elevated test-owner permissions.

The local SQL Express instance is Windows-authentication-only. Its interactive development connection remains the current Windows identity. This change does not enable mixed authentication, create server logins, or restart SQL Server. Distinct runtime login provisioning is still needed for a fully restricted local runtime; multiple integrated-security connection strings under the same process identity do not create separate identities.
