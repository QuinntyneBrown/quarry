# Operational health

Anonymous `/health/live` reports process liveness. `/health/ready` and `/health/catalog` verify catalog tables and state with a three-second bound. `/health/search` checks current compatible vectors and a bounded synthetic embedding probe; `/health/indexing` checks stored index usability without calling embeddings. Each public body contains only `status`; unhealthy or degraded dependencies return 503. A healthy empty catalog is ready.

`GET /api/maintenance/diagnostics` requires the maintenance JWT permission before checks execute. It returns a correlation ID and independent catalog, search, and indexing statuses, safe issue categories, published/searchable/pending counts, active retry failures, oldest pending age, the 60-second freshness flag, and source/indexed revisions. Pending means a published entry lacks a usable vector for its current revision and embedding profile. Age uses publication time, falling back to durable work creation time for legacy/test rows; an unavailable age remains null. Completed work and withdrawn entries do not contribute retry failures. Zero, malformed, or dimension-incompatible vectors are not searchable.

The probe uses the fixed text `quarry-health-v1`, never user queries, and the existing provider validates the pinned digest and dimensions. The whole search/diagnostic check has an eight-second bound. Operator issue codes map to actions: `catalog_configuration_invalid` means repair the connection configuration; `catalog_unavailable` means inspect SQL availability/migrations; `embedding_configuration_invalid` means correct endpoint/model/digest/dimensions; `embedding_unavailable` means check Ollama; `embedding_incompatible` means restore the pinned model; `index_incomplete` and `index_freshness_exceeded` mean inspect the indexing worker and retry backlog.

ATDD on 2026-09-10: the first three SQL-backed scenarios failed on absent routes. They now cover authorization before probes, coarse public responses, empty-catalog readiness, stale revision/retry/freshness diagnostics, completion recovery, embedding failure, and invalid embedding configuration. Two additional scenarios cover corrupt vectors/model mismatch and malformed persistence settings; malformed settings initially returned 500 and now produce safe 503 health with actionable protected guidance.

This slice supplies health reports and index metrics. [Diagnostic events](diagnostic-events.md) cover request and index operation logging. Measured freshness/rebuild performance remains a separate gate.
