# Actual 200% browser zoom

L2-027 requires a 1280 × 900 browser window at 200% zoom. The `browser-zoom` Playwright project uses bundled Chromium, an ephemeral persistent profile, and a test-only Manifest V3 extension limited to the local test host. It follows [Playwright's extension setup](https://playwright.dev/docs/chrome-extensions) and invokes [`chrome.tabs.setZoom`](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-setZoom). It does not change the user's browser profile.

Every scenario verifies the physical window dimensions, initial device scale 1, browser zoom factor 2, final device scale 2, and unchanged CSS `zoom: 1`. The setup also verifies that the content width halves. On this Windows host the browser border leaves 1258 physical content pixels, becoming 629 CSS pixels at 200%. Each test retains a JSON attachment with before/after measurements and the browser-reported zoom factor.

All existing interaction scenarios join this project: submission and examples, filtering, pagination and revision conflicts, cancellation, details and keyboard boundaries, selection and unavailable states, query validation, quotas, preview isolation/recovery, and accessibility checks. Two additional scenarios measure horizontal overflow, reachable actions, pointer targets, a 500-character unbroken query, loading/error/empty states, and the real sandbox preview's inputs, switch, save, and reset. All API traffic uses shared mocks.

The initial acceptance test failed with a zoom factor of 1 and an 800 × 600 window, demonstrating that the test does not mistake a normal viewport for browser zoom. Subsequent verification corrected a page object's assumption that every viewport is emulated. A contrast audit of a scrolled dialog also required exposing the affected text through scrolling before measuring its solid-background contrast. The fallback accepts only findings identifying the containing dialog as the obscurer; other incomplete findings continue to fail.

Native viewport captures use [DevTools `Page.captureScreenshot`](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-captureScreenshot), avoiding the cropped images produced by Playwright's screenshot clipping calculations at browser zoom. The detail actions and real preview captures were visually reviewed. Focused zoom, accessibility, and modal checks passed all six tests. No application behavior was changed by this verification increment.

The final regression run passed **122 tests in 2.0 minutes** with `CI=true` and two workers: 62 at actual 200% zoom and 60 at XS. Type checking and both workspace builds passed. The zoom project is part of the default CI browser command; its reports and captures are retained with the existing test artifacts.
